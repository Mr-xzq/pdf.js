# Complex PDF Reader 瘦身原则与实施指南

> 目的：在不影响现有功能的前提下，系统性移除冗余实现与无效依赖，降低维护成本、代码复杂度与运行时开销。

## 1. 适用范围
- 目录：examples/web-vue2/src/components/complexPdfReader/components/pdfReaderCore/**
- 侧重模块：core（pdf-application、pdf-services、pdf-config、scale、layers/*、components/*）
- 不在本轮范围：官方 web/ 完整 Viewer（web/ 目录）仅作为参考实现，不被直接集成

## 2. 总体策略
- 以最终产品功能为导向：只保留为“当前功能”必需的代码路径与依赖
- Store 为单一事实来源：状态通过 Vuex 同步与驱动，组件以 watcher 响应
- 去桥接、减耦合：默认不做“事件桥接层”；确有必要时再按需、最小化接入
- 小步快跑、可回滚：每次改动有明确验证清单，必要时可快速回退

## 3. 事件系统瘦身（当前决定）
- 不依赖 web/ 官方 Viewer 的事件流（如 pagechanging、scalechanging、updateviewarea 等）
- 不实例化 PDFViewer/PDFSinglePageViewer，仅使用：
  - EventBus（事件总线）
  - PDFLinkService（内部链接/命名目的地解析）
- 已移除事件桥接器（EventBridge）：
  - 移除 pdf-events.js 文件
  - 移除 PdfServices 中对 EventBridge 的导入/实例化/销毁
  - core/index.js 不再导出 pdf-events
- 页码/缩放等状态变化路径：Vuex -> PdfViewport watcher -> 组件内部渲染/重排 -> 对外 $emit（如 page-changed、scale-changed）

当且仅当出现以下“明确需求”时，才考虑监听 PDF.js EventBus 事件（且放在组件/服务内最小接入）：
- URL/历史同步：需要 updateviewarea/pagesinit/pagesloaded
- 页面渲染观测：需要 pagerendered/pagerender（性能/占位）
- 特定交互钩子：linkclicked、optionalcontentconfigchanged 等

## 4. 依赖取舍（web/ vs 自研）
- ✅ 引入：EventBus、PDFLinkService、PDFFindController（如需全文检索）
- ❌ 排除：PDFViewer、PDFThumbnailViewer、PDFOutlineViewer 等 UI 固化组件
- ✅ 保留：pdf-config 统一 Worker 配置、样式副作用集中管理（pdf_viewer.css 仅在需要时注入）

## 5. 状态管理与数据流（权威）
- 统一使用 Vuex 模块 `pdfReader`：
  - viewer：currentPage、scale、导航相关派发（goToPage/next/prev/setScale/zoomIn/zoomOut）
  - document：loaded/loading/totalPages/错误信息/进度（如需要）
- 组件侧（PdfViewport 等）：
  - 通过 mapState 映射只读状态
  - 通过 watcher 响应 store 变化，同步到核心渲染（避免循环：仅当本地值与 store 不一致时更新）
  - 对外统一 $emit 业务语义事件（document-loaded/page-changed/scale-changed 等）

## 7. 扩展功能接入原则（按需开启）
- URL/历史同步
  - 仅在确有需求时监听 updateviewarea/pagesinit/pagesloaded
  - 优先使用 PDFHistory + PDFLinkService 组合；Vue2 侧只接 UI 值
- 渲染观测/性能优化
  - 仅在需要精确观测时监听 pagerendered；默认不监听
- 交互增强
  - 链接拦截（linkclicked）等仅在有明确业务落地时引入
- 所有新增监听都应：
  - 在单一位置注册与销毁
  - 有明确的目的、数据流与验证用例
  - 通过 Feature Flag 或可开关配置托管

## 8. 验证与回归测试清单
- 功能冒烟
  - 加载/错误提示/进度（如有）
  - 翻页（输入/按钮/手势）
  - 缩放（按钮/手势）
- 状态一致性
  - Vuex 中的 currentPage/scale 与组件内部状态保持一致
  - 组件 watcher 不出现循环更新（仅在不一致时同步）
- 事件对外协议
  - document-loaded/page-changed/scale-changed/page-rendered 等按预期触发
- 依赖与资源
  - Worker 配置与样式副作用无警告（无 fake worker 提示）

## 9. 变更管理与回滚
- 每次瘦身改动：
  - 具备代码 diff 列表与影响面说明
  - 附验证清单与结论
- 可回滚策略：
  - 单文件/单功能改动可逐步 revert
  - 涉及文档的说明可以延后同步，但须标记 TODO

## 10. 当前架构事实（2025-09）
- 未实例化官方 PDFViewer；不依赖其派发的 pagechanging/scalechanging
- 核心服务使用 EventBus + PDFLinkService；状态流由 Vuex 驱动
- 事件桥接层（EventBridge）已移除；不再从 EventBus 转发到 Vue 组件
- PdfViewport 以 watcher 响应 store，驱动渲染并对外 $emit 语义事件

- core/index.js 不再导出 pdf-config；pdf_viewer.css 仅在显式 import 时按需注入
- PageRenderService 已移除缓存相关实现；PdfPage.vue 不再调用 clearCache

本指南作为后续瘦身与增量开发的约束与参考，若有新需求引入“事件监听/官方组件”等，请先提交最小设计方案，评估其对既有数据流与性能的影响后再实施。


## 11. 进一步可瘦身项（候选清单）

> 以下为在不改变现有功能的前提下，可继续推进的瘦身候选；建议按优先级逐项实施，并在每项执行后做一次最小验证。

- 移除 ControlsService 及组件内回退分支（高优先）
  - 现状：组件方法存在“无 Store 回退 ControlsService”的分支，但 ControlsService 本身也依赖全局 Vuex；因此回退路径实际无意义。
  - 动作：
    - PdfViewport.vue：删除 controlsService 成员与实例化；删除 goToPage/next/prev/setScale 中对 controlsService 的回退逻辑，统一走 Vuex actions。
    - core/pdf-services.js：如无外部直接引用，移除 ControlsService 导出与实现。
  - 影响面：对外 API 不变（仍通过 Vuex 驱动）；减少一层间接与状态来源。

- 清理未使用的 Props/Options（高优先）
  - PdfViewport.vue：
    - maxCanvasPixels（未被使用）→ 标记废弃并移除；
    - textLayerMode（从 props 透传但当前路径未使用）→ 标记废弃并移除。
  - PdfReaderCore/index.vue：确认 autoPlay 若业务侧未使用，可下放为“示例功能”，默认不暴露或以 Feature Flag 控制。

- 移除未使用的组件导入（高优先）
  - PdfViewport.vue 已不再在模板渲染 PdfLoadingProgress（转用 Toast），可移除其 import 与 components 注册，避免无意义打包体积。

- 降噪日志（中优先）
  - 将 console.log/console.debug 改为开发环境可控（例如通过简单的 DEBUG 开关或基于 NODE_ENV）。
  - PageRenderService/PdfViewport 等高频日志建议保留 warn/error，其余默认关闭。

- pdf-config 与样式副作用（状态：已完成）
  - 变更：core/index.js 已移除对 pdf-config 的导出；pdf_viewer.css 仅在显式 import "./pdf-config.js" 的文件中按需注入。
  - 原则：纯工具模块避免从 core/index.js 整体导入，按需导入所需模块，减少样式副作用。
  - 备注：initializePdfViewer 如无额外逻辑，可与 getPdfjsViewer 合并（后续可选）。


- READER_CONFIG 精简（状态：已完成）
  - 变更：仅保留 enableScripting=false，移除无效项（如 textLayerMode/annotationMode）。
  - 现状：pdf-loader.js 将 READER_CONFIG 合并进 getDocument 参数，最小化传参。

- PageRenderService 缓存路径复查（状态：已完成）
  - 变更：已移除 renderCache/cacheKeys 及 clearCache/setCache/getCache/hasCache/deleteCache 等方法；PdfPage.vue 中的 clearCache 调用同步删除。
  - 现状：当前渲染路径未使用缓存；若未来需要缩略图/预览缓存，建议独立实现具备容量与淘汰策略的专用模块并补文档。

- 事件转发链路收敛（低优先，当前暂缓）
  - 现状：PdfViewport 向父组件转发 load-progress 等事件；父层若仅透传或未消费，可考虑直接依赖 Vuex 的进度状态，移除无用事件通道。

- 文档对齐与注释收敛（低优先）
  - 将文档中仍提及 EventBridge/官方事件桥接的段落统一更新为“Vuex 驱动 + 组件 watcher”。
  - 将“为何需要 pdf_viewer.css”说明写清：TextLayer/AnnotationLayer 使用官方 Builder，依赖其样式；除非自实现对应样式，否则不可移除。
